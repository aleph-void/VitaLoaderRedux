# Credits: Toshiba MeP module

This module is a community SLEIGH module that Ghidra-Rare imported, tested and fixed. The MeP
processor specification comes from VitaLoader Redux, a PlayStation Vita reverse-engineering
extension; Ghidra-Rare moved it into this standalone module directory, completed the core
instruction set, added the IVC2 coprocessor and the VLIW mode, and fixed what testing found.

No code was copied from the alternatives or from GNU binutils/GCC. Core encodings follow the MeP
instruction set (as the original author did, from the MeP-c4 manual) and were checked against
GNU binutils 2.45 (objdump); the IVC2 encodings were learned from objdump as a black box
(`tools/ivc2_learn.py`), with binutils' opcode table used only to seed the search with one
encoding per entry and to name each operand's role. Measured against objdump on the same

## Ghidra-Rare changes

Each item names the problem and how it was found.

1. **Standalone module** `MeP/` (the language files moved from `data/languages/MeP-c5`, with
   their history). The repository's Vita ELF-PRX loader only creates ARM programs, so it is not
   part of this module; it stays at the repository root, unchanged.
2. **Core instruction set completed** (README: "MeP-c5 instructions are not implemented",
   "Coprocessor-modulo instructions are not implemented"): CASB3/CASH3/CASW3, STCB/LDCB (Rm),
   PREF disp16(Rm), the c5 coprocessor loads/stores with 12-bit displacement and zero
   extension, coprocessor post-increment/modulo loads and stores with the c5 10-bit
   displacement, JSRV/BSRV, UCI, DSP, the simulator system call. Found by differential testing.
3. **Semantics**: NEG computed ~Rm; SSARB used the wrong endianness; DIV/DIVU had no
   divide-by-zero or 0x80000000/-1 case; SADD lacked underflow, SSUB overflow; REPEAT/EREPEAT
   kept RPC off by one and branched at the wrong instruction for the architected RPC; DI/EI,
   HALT, RETI (NMI/EPC, IEC/UMC restore), SWI, DRET, DBREAK now update PSW/EXC/DBG; STC writes
   only each control register's writable bits (upstream TODO "SOME BITS ARE SUPPOSED TO BE
   READ-ONLY"); 32-bit coprocessor transfers on big-endian. Found by emulator tests.
4. **Real-binary fixes**: GCC returns with `jmp $11` (every non-leaf function); JMP $1 is a
   switch-table jump in GCC code, so it is no longer a return; GCC's mode-switching sibling
   call `stc $12,$lp; jmp $11` is a jump. Found by GCC-built binaries.
5. **IVC2 coprocessor and VLIW mode** (README: "IVC2 coprocessor (i.e. Venezia core) is not
   implemented"; "Future plans: Venezia (MeP + IVC2) support"): new languages
   `MeP-c5:LE:32:IVC2`/`MeP-c5:BE:32:IVC2` with all 293 core-mode IVC2 instructions and 64-bit
   VLIW bundles (P0S/P0/P1 slots, 588 slot forms), generated by `tools/gen_ivc2.py` from the
   spec `tools/ivc2_learn.py` learned from objdump; ELF extension that switches `.vtext`
   (SHF_MEP_VLIW) sections to VLIW mode; BSRV mode switch; VLIW repeat blocks.
6. **Languages and spec files**: big-endian language (GCC's `-meb`), `MeP-c5:LE:32:default`
   with every option, GCC calling convention (upstream had $9-$12 callee-saved; values over 4
   bytes by reference, hidden return pointer), DWARF register map, control bus as a volatile
   `cbus` space with the interrupt-controller and timer names upstream had as registers,
   opinion by byte order and coprocessor (`e_flags`).
7. **Relocation handler** for relocatable objects (all MeP relocation types).

Ghidra-Rare additions: `GHIDRA-RARE.md`, `CREDITS.md`, `build.gradle`, `extension.properties`,
`test/`, `tools/`; the repository README's MeP section was updated.
